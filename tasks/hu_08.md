Instrucciones para Generar y Corregir el Build de Producción (Monorepo Eruditia: Turborepo + Bun + NestJS + Next.js 16)

1. Objetivo de esta Tarea (Prompt para el Agente de IA)

Actúa como Ingeniero DevOps / Full-Stack Senior en el monorepo Eruditia (bun + turbo, con apps/api en NestJS + Sequelize + PostgreSQL y apps/web en Next.js 16 App Router + React 19 + Tailwind 4).

Tu objetivo es preparar, ejecutar y dejar pasando al 100% el build de producción de todo el monorepo (bun run build), corrigiendo cualquier error de compilación de TypeScript, empaquetado de paquetes compartidos, assets de NestJS o prerenderizado estático de Next.js 16.

2. Paso a Paso que debes ejecutar y verificar

Paso 1: Auditar package.json raíz y turbo.json

Revisa el package.json de la raíz y verifica que exista el script "build": "turbo run build" (o "turbo build").

Revisa turbo.json y asegúrate de que la tarea build esté configurada correctamente para un monorepo con Next.js y NestJS:

"dependsOn": ["^build"] (para que cualquier paquete compartido en packages/* se compile antes que apps/api y apps/web).

"outputs": ["dist/**", ".next/**", "!.next/cache/**"].

Declara en env las variables necesarias en tiempo de compilación (como NEXT_PUBLIC_API_URL, NODE_ENV).

Paso 2: Compilar primero los paquetes compartidos (packages/*) y el Backend (apps/api - NestJS)

Si existen paquetes compartidos en packages/* que exportan código compilado, verifica sus scripts build y ejecútalos primero.

Ejecuta el chequeo de tipos y el build del backend:

bun --cwd apps/api run build


Verificaciones y correcciones críticas en apps/api:

Confirma que apps/api/tsconfig.build.json excluya archivos de test (**/*.spec.ts, **/*.test.ts) y mantenga "emitDecoratorMetadata": true y "experimentalDecorators": true para Sequelize y NestJS.

Si el generador de PDFs de boletines o de correos usa plantillas, fuentes o archivos estáticos fuera de .ts, asegúrate de declararlos en apps/api/nest-cli.json dentro de "compilerOptions": { "assets": [...], "watchAssets": true } para que se copien a apps/api/dist/.

Comprueba que se haya generado el archivo de entrada en apps/api/dist/main.js y que el script "start:prod": "node dist/main.js" (o "bun dist/main.js") esté correctamente definido en apps/api/package.json.

Paso 3: Compilar el Frontend (apps/web - Next.js 16 + React 19)

Ejecuta el build de producción del frontend:

bun --cwd apps/web run build


Errores frecuentes en Next.js 16 App Router que debes buscar y corregir si aparecen:

params y searchParams asíncronos: En Next.js 15/16, params y searchParams en page.tsx, layout.tsx y route.ts son promesas (Promise<{ ... }>). Verifica que todas las rutas dinámicas (/estudiantes/[id], /salones/[id], /mis-clases/[classroomId], /planillas/[classroomSubjectId], /consulta-notas/[org_slug]) hagan await params o React.use(params) correctamente con su tipado exacto.

Uso de useSearchParams() en Client Components: Cualquier componente cliente que use useSearchParams() debe estar envuelto en un <Suspense fallback={...}> para que next build no falle al intentar prerenderizar la ruta.

Rutas que dependen de Cookies / Sesión en Build Time: Si alguna página del panel intenta leer cookies o llamar a la API durante el prerenderizado estático sin sesión y falla en el build, agrégale export const dynamic = 'force-dynamic' en el page.tsx o layout.tsx correspondiente.

Errores estrictos de TypeScript / ESLint: Corrige cualquier tipo implícito any, import no utilizado o desajuste de props entre componentes de shadcn/ui (Base UI) y las páginas creadas en las HU-01 a HU-07.

Paso 4: Ejecutar el Build Global con Turborepo sin Caché

Una vez que apps/api y apps/web compilen individualmente sin errores, ejecuta el build completo desde la raíz ignorando la caché para confirmar que el pipeline de Turborepo funciona limpio de principio a fin:

bunx turbo run build --force


Paso 5: Preparación de Archivos para Despliegue

En apps/web/next.config.ts (o .mjs), habilita output: 'standalone' si el proyecto se va a desplegar en Docker / VPS / Railway / Render, o déjalo listo para Vercel + servidor Node/Bun.

Verifica o actualiza los archivos .env.example en apps/api/.env.example y apps/web/.env.example documentando todas las variables de entorno requeridas en producción:

En apps/api: PORT, NODE_ENV=production, DATABASE_URL (o DB_HOST, DB_PORT, DB_USER, DB_PASSWORD, DB_NAME), CORS_ORIGIN (dominio del frontend), variables de SMTP/correo para envío de contraseñas y 2FA, y configuración trust proxy.

En apps/web: NEXT_PUBLIC_API_URL (URL pública de la API en producción).

Entrégame al finalizar un reporte indicando:

Qué errores de compilación encontraste y cómo los corregiste.

La salida exitosa de bunx turbo run build --force.

Los comandos exactos para iniciar apps/api y apps/web en producción.
